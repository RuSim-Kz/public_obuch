## 1. Цель работы

Целью учебной практики является проектирование и реализация структуры базы данных для портала дополнительного профессионального образования **«Корочки.есть»**. В рамках работы необходимо было:

- изучить предметную область и выделить сущности с атрибутами;
- построить ER-диаграмму связей между таблицами;
- создать базу данных **korochki_portal** в СУБД PostgreSQL;
- реализовать таблицы **users**, **payment_methods**, **applications** с внешними ключами;
- заполнить справочники и тестовые данные;
- проверить целостность связей SQL-запросами;
- разработать PHP-скрипты для подключения к БД и отображения данных в браузере.

Портал предназначен для регистрации пользователей, подачи заявок на обучение, выбора способа оплаты и отслеживания статуса заявки администратором.

## 2. Этап 1. Анализ предметной области

### Задание 1.1. Изучение описания предметной области

При анализе предметной области были выделены следующие ключевые сведения.

**Регистрация пользователя.** Для регистрации требуются: логин (латиница и цифры, не менее 6 символов), пароль (не менее 8 символов, хранится в хэшированном виде), ФИО (кириллица и пробелы), телефон в формате `8(XXX)XXX-XX-XX`, адрес электронной почты, роль пользователя.

**Подача заявки.** Пользователь указывает название курса, желаемую дату начала обучения и способ оплаты.

**Статусы заявки.** Возможные значения: «Новая», «Идет обучение», «Обучение завершено».

**Роли.** В системе предусмотрены роли **user** (обычный пользователь) и **admin** (администратор).

**Способы оплаты.** Справочник содержит: «Наличные» и «Перевод по номеру телефона».

---

### Задание 1.2. Определение сущностей и атрибутов

Ниже приведено текстовое описание трёх сущностей. Полная таблица атрибутов сохранена в отдельном файле проекта.

#### Сущность «Пользователи» (users)

| Атрибут    | Описание                         | Тип данных  | Ограничения                                      |
|------------|----------------------------------|-------------|--------------------------------------------------|
| id         | Уникальный идентификатор         | целое число | первичный ключ, автоинкремент                    |
| login      | Логин для входа                  | строка      | уникальный, латиница и цифры, не менее 6 символов |
| password   | Пароль                           | строка      | минимум 8 символов, хранить в хэшированном виде  |
| full_name  | ФИО пользователя                 | строка      | кириллица и пробелы                              |
| phone      | Номер телефона                   | строка      | формат 8(XXX)XXX-XX-XX                           |
| email      | Адрес электронной почты          | строка      | формат email                                     |
| role       | Роль пользователя                | строка      | 'user' или 'admin'                               |
| created_at | Дата и время регистрации         | дата/время  | по умолчанию — текущая дата                      |

#### Сущность «Способы оплаты» (payment_methods)

| Атрибут | Описание                | Тип данных  | Ограничения                                              |
|---------|-------------------------|-------------|----------------------------------------------------------|
| id      | Уникальный идентификатор| целое число | первичный ключ, автоинкремент                            |
| name    | Название способа оплаты | строка      | «Наличные», «Перевод по номеру телефона»                 |

#### Сущность «Заявки» (applications)

| Атрибут            | Описание                      | Тип данных  | Ограничения                                              |
|--------------------|-------------------------------|-------------|----------------------------------------------------------|
| id                 | Уникальный идентификатор      | целое число | первичный ключ, автоинкремент                            |
| user_id            | Автор заявки                  | целое число | внешний ключ к users.id                                  |
| course_name        | Название курса                | строка      | не пустое                                                |
| desired_start_date | Желаемая дата начала обучения | дата        | не пустое                                                |
| payment_method_id  | Способ оплаты                 | целое число | внешний ключ к payment_methods.id                        |
| status             | Статус заявки                 | строка      | «Новая», «Идет обучение», «Обучение завершено»           |
| created_at         | Дата подачи заявки            | дата/время  | по умолчанию — текущая дата                              |
| review             | Отзыв о качестве обучения     | текст       | может быть пустым (NULL)                                 |

#### Связи между сущностями

- Один пользователь (**users**) может подать **много заявок** (**applications**) — связь 1:N.
- Один способ оплаты (**payment_methods**) может использоваться в **многих заявках** — связь 1:N.


## 6. Настройка окружения (PostgreSQL, PHP, XAMPP)

### 6.1. Установка PostgreSQL 16

- Установлен сервер PostgreSQL 16 и pgAdmin 4.
- Задан пароль пользователя **postgres** при установке.
- Служба **postgresql-x64-16** запущена и работает на порту **5432**.

**Примечания по установщику:**

- Обязательно: **Database Server**, **pgAdmin**.
- Не требуется: PostGIS (Spatial Extensions), pgAgent, pgBouncer, MySQL.

---

### 6.2. Настройка PHP (расширение pgsql)

Для работы функций `pg_connect`, `pg_query` и др. в файле **php.ini** включены:

```ini
extension_dir = "C:\Program Files (x86)\php\ext"
extension=pgsql
extension=pdo_pgsql
```

(При использовании XAMPP путь к php.ini: `C:\xampp\php\php.ini`)

В переменную среды **Path** добавлен каталог:

```
C:\Program Files\PostgreSQL\16\bin
```

(нужен для библиотеки **libpq.dll**)

**Проверка в командной строке:**

```
[ВСТАВИТЬ ВЫВОД: php -m | findstr pgsql]
```

Ожидаемый результат: строки `pgsql` и `pdo_pgsql`.

---

### 6.3. Установка XAMPP

XAMPP используется как веб-сервер Apache для открытия PHP-страниц в браузере.

### Задание 4.2. Обработчик авторизации (login_handler.php)

**Назначение:** принять POST-данные логина и пароля, найти пользователя в БД, проверить пароль, сохранить данные пользователя в `$_SESSION`.

**Логика работы:**

- если запрос не POST → редирект на `login.php`;
- если логин/пароль не заполнены → `$_SESSION['login_error']` и возврат на `login.php`;
- поиск пользователя через `findUserByLogin()` (из `php/user_functions.php`);
- проверка пароля через `password_verify()` по хэшу в таблице `users`;
- при успехе создаётся `$_SESSION['user']` (id, login, full_name, role).

**Файл:** `php/login_handler.php`

```
[ВСТАВИТЬ КОД]
```
